## Batch 1 — recover the same original-photo session

`intakeSession.ts` freezes actual owner, explicit run UUID, mode, context and each original photograph's path, size, index and SHA-256 before writes. A lost INSERT response is resolved by a fresh owner-scoped read of that same identity and exact manifest. Each original is independently downloaded and byte/hash checked. A retry reuses confirmed originals; only a definite not-found result permits retrying an unconfirmed upload at its original path. Original files are not transformed, replaced or silently removed.

AI Intake holds the original request and prevents conflicting changes during uncertainty. Held details are copyable/read-only. Before dispatch it checks the actual owner/session, saved stage, original bytes and fresh signed links. A page-local dispatch flag is set before the single provider POST. A timeout/lost reply leads to **Check saved analysis**, which reads only; it cannot become an automatic second paid request. An unconfirmed service reply is shown separately from saved session data as escaped raw text. Exact saved COMPLETE/retained FIRST_PASS_SAVED reports with render-safe shapes open the existing SavedDraft route after original-byte verification. This reuses the established review, correction, pair, research and catalogue workflow instead of maintaining a second approval implementation.
